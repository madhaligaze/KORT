# 1С для нового клиента и AnyDesk - заметки (18.11.2026)

## Задача клиента

Новый клиент переносит данные из 1С в Google Таблицы руками. Хочет, чтобы
программа сама брала данные из 1С и заносила их в Google Таблицу через
сервисный аккаунт Google.

1С у клиента облачная, но не 1С:Fresh (ответ клиента 18.11).

## Что уже есть в KORT («Интеграции → 1С»)

Код: `backend/app/finance/onec/` (`client.py`, `sync.py`, `match.py`,
`service.py`, `models.py`), маршруты `backend/app/api/routes/finance_onec.py`,
шифрование пароля `backend/app/finance/secretbox.py`, экран `onec-panel.tsx`.

- **Подключение** - автоматический REST-сервис 1С (OData): адрес, пользователь,
  пароль (хранится зашифрованным ключом `FINANCE_SECRETS_KEY`). Отказы 1С
  объясняются словами. Чтение по кнопке и в фоне каждые
  `FINANCE_ONEC_SYNC_MINUTES` минут (по умолчанию 30).
- **Что читается:** счета на оплату (`Document_СчетНаОплатуПокупателю`),
  реализации/АВР (`Document_РеализацияТоваровУслуг`), дата подписания акта
  (`InformationRegister_СведенияПоАктамВыполненныхРабот`), входящие платёжки
  (`Document_ПлатежноеПоручениеВходящее`), счета-фактуры
  (`Document_СчетФактураВыданный`), ЭСФ (`Document_ЭСФ`), контрагенты, договоры,
  организации. В 1С не пишется ничего.
- **Раскладка** по договорам реестра и месяцам: Клиент | Договор | Счёт |
  Оплата | АВР | Подписан | ЭСФ; список «без договора» с кандидатами.
- **Google Таблицы** - чтение и запись через сервисный аккаунт. Запись сейчас
  одна: номер и дата счёта в таблицу юрлица (колонки ищутся по названиям,
  запись одним пакетом, чужая правка не перезаписывается) -
  `backend/app/finance/contracts/bill_book.py`, `backend/app/finance/google.py`.
- В спящем ядре есть ещё чтение ОСВ, сальдо и файлов 1С
  (`onec/osv.py`, `onec/balances.py`, `onec/files.py`) - не подключено.

**Чего нет:**

- к настоящей базе клиента KORT не подключали ни разу - только к нашей
  тестовой 1С:Fresh с данными BBC;
- набор объектов фиксирован под «Бухгалтерию для Казахстана» и задачи BBC;
  другая конфигурация или другие отчёты - дописывать чтение;
- нет пути «1С → любая Google-таблица клиента»: данные из 1С идут в экраны KORT;
- KORT работает в облаке (Railway) и видит только 1С, доступную из интернета.

## Решение

С нуля не писать: клиент OData, сопоставление по названиям и запись в Google
уже есть. Форма зависит от того, где стоит 1С:

- **1С доступна из интернета по OData** (облако провайдера с веб-публикацией,
  1С:Fresh) - делать внутри KORT: клиент становится компанией в KORT,
  подключаем его 1С, добавляем «выгрузку в Google Таблицу» по названиям колонок.
- **Локальная база без публикации** - небольшая утилита на их компьютере
  (COM-подключение или локальный OData) пишет в Google Таблицы сама; маппинг и
  запись в Google взять из KORT.

У клиента облако не Fresh - значит первый вариант, если провайдер даёт OData.

## Что выяснить у клиента

1. Как входят в 1С: через браузер (адрес вида `https://…/имя_базы/`) или через
   удалённый рабочий стол / ярлык, который открывает 1С на сервере провайдера.
2. Название провайдера.
3. Конфигурация и версия 1С: «Справка → О программе», скриншот окна.
4. Ссылка на их Google-таблицу (или копия) и какие колонки из каких
   документов или отчётов 1С сейчас переносят руками.
5. Как часто обновлять; нужен ли им сам KORT или только таблицы.

**Вход через браузер:** веб-публикация есть, OData обычно на том же адресе -
`…/odata/standard.odata/`. Включить в базе: в «Администрировании» - настройка
стандартного интерфейса OData (выбрать состав объектов), завести отдельного
пользователя. Если провайдер отключил OData в публикации - просить его
поддержку.

**Вход через удалённый рабочий стол:** веб-публикации может не быть. Без
провайдера никак - он публикует базу с OData. Свою программу на сервер
провайдера обычно не пускают, прямые порты сервера 1С закрыты.

Письмо в поддержку провайдера:

```
Здравствуйте. Просим для нашей базы «<имя базы>» опубликовать стандартный
интерфейс OData (standard.odata) с доступом по HTTPS из интернета.
Нужен для чтения данных внешней программой (только чтение).
Пользователя 1С для доступа заведём сами. Сообщите, пожалуйста,
адрес публикации и есть ли ограничения по IP-адресам.
```

**Проверка доступа,** когда будут адрес и пользователь:
`GET <адрес>/odata/standard.odata/` - 200 и список объектов: открыто;
401: неверный пользователь или пароль; 404: OData не опубликован.

## AnyDesk и управление компьютером

- AnyDesk 9.8.3 установлен 18.11 (winget `AnyDesk.AnyDesk`, установщик с
  `download.anydesk.com`, хеш сверен). Служба на автозапуске, неуправляемый
  доступ выключен - каждое подключение принимается в окне.
- В сессии VS Code Claude экрана не видит и мышью не управляет - только
  командная строка на этом компьютере.
- Управление экраном - приложение Claude для компьютера с включённым
  Computer use: Claude видит экран и кликает, в том числе в окне AnyDesk, то
  есть может зайти в 1С на компьютере бухгалтера.
- Порядок: бухгалтер принимает подключение AnyDesk и знает о настройке; в 1С
  Claude только настраивает (OData, состав объектов, пользователь для доступа).
  Документы, платежи и проводки не проводит.
- В интерфейсе 1С нужно немного: включить OData с составом объектов и завести
  пользователя. Остальное - через API отсюда.
